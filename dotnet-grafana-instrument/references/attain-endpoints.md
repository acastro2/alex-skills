# Attain endpoints, conventions, and rules

## The four gateways

All internal, resolvable only on the Attain network / VPN (`observability-internal.attainfinance.com`). Prefer HTTPS on 443; fall back to HTTP on 80 only if the TLS handshake fails (hardened Windows SCHANNEL hosts, see `dotnet-framework-iis.md`).

| Signal | Backend (datasource uid) | Endpoint | OTLP path |
|---|---|---|---|
| Metrics | Mimir (`eeou8qj3gbvgge`) | `https://mimir.observability-internal.attainfinance.com/otlp` | needs `/otlp` suffix |
| Logs | Loki (`eeou8ipbcojcwc`, default) | `https://loki.observability-internal.attainfinance.com/otlp` | needs `/otlp` suffix |
| Traces | Tempo (`aeou8l7tjqk8wd`) | `https://tempo.observability-internal.attainfinance.com` | root (no suffix) |
| Profiles | Pyroscope (`bfojmhghtbhtsc`) | `https://pyroscope.observability-internal.attainfinance.com` | Pyroscope SDK push |

Path behavior (OTLP/http): the **base** `OTEL_EXPORTER_OTLP_ENDPOINT` gets `/v1/traces`, `/v1/metrics`, `/v1/logs` appended automatically per signal. **Per-signal** vars (`OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, etc.) are used **exactly as given** with no append, so for direct-to-gateway spell out the full path (`mimir.../otlp/v1/metrics`, `loki.../otlp/v1/logs`, `tempo.../v1/traces`). Loki's native OTLP auto-promotes the standard resource attributes (`service.name`, `service.namespace`, `service.instance.id`, `deployment.environment`) to index labels; everything else becomes structured metadata.

Most apps do not send to these directly. They send OTLP to a **local collector or node Alloy** (base endpoint `http://localhost:4318`, paths auto-appended) that fans out to these gateways. Direct-to-gateway is for local verification and some EC2 cases. See `deployment-targets.md`.

## Environment variables (the contract)

```bash
OTEL_SERVICE_NAME=myservice                 # lowercase, becomes service_name label
OTEL_RESOURCE_ATTRIBUTES=service.namespace=lending,service.version=1.4.2,deployment.environment=Prod
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf   # http/protobuf is the Attain default
OTEL_EXPORTER_OTLP_ENDPOINT=...             # per target (deployment-targets.md)
PYROSCOPE_SERVER_ADDRESS=https://pyroscope.observability-internal.attainfinance.com
PYROSCOPE_APPLICATION_NAME=myservice
```

## Resource attributes (set on every signal)

| Attribute | Example | Why |
|---|---|---|
| `service.name` | `myservice` | The join key across metrics/logs/traces/profiles. Lowercase. |
| `service.version` | `1.4.2` | Correlate behavior to deploys. From the assembly version. |
| `service.namespace` | `lending` | Groups related services. |
| `service.instance.id` | host or pod name | Distinguishes replicas. |
| `deployment.environment` | `Prod` / `NONPROD` / `local` | Dashboards filter on this. Exact match, not regex. |

## Conventions (match these or dashboards break)

- **`service.name` / `service_name` is lowercase** everywhere. The collector lowercases it; dashboard queries assume lowercase.
- **`deployment.environment`** values: `Prod`, `NONPROD`, `local`. Promoted to the `deployment_environment` label by the collector/Alloy transform.
- **`host_name`** is the OS hostname as-is (often UPPERCASE on Windows). Host-level logs (Windows event logs) carry `service_name=unknown_service`: query those by `host_name`.
- Metric names follow OTel semconv: HTTP server latency is `http_server_request_duration` (histogram), so the count series is `http_server_request_duration_count{service_name="myservice"}`.
- Span metrics (RED) generated by Tempo: `traces_spanmetrics_calls_total{service="myservice"}`. If these exist, traces are flowing even if a dashboard panel is misconfigured.

## PII and cardinality (non-negotiable)

This is regulated lending data (SR 11-7, ECOA/Reg B, PCI). 

- **Never** put SSN, PAN/card number, full email, DOB, full name, account number, or auth tokens in: span attributes, span names, metric labels, log message bodies, exemplar attributes, or Pyroscope labels. The pipeline redacts SSN/CC/email patterns as a backstop only.
- **Cardinality:** never use unbounded values (user id, request id, full URL with path ids, raw SQL with literals) as metric label values or as indexed log/trace labels. Use route templates (`/loans/{id}`), bucket values, or put high-cardinality detail in span attributes (Tempo handles high cardinality), never in metric labels (Mimir does not).

## Correlation (already wired in Grafana, your job is to feed it)

Tempo is configured with tracesToLogsV2 (Loki via `trace_id`), tracesToMetrics (RED), and tracesToProfiles (Pyroscope CPU). Loki has a derived field `trace_id` to Tempo. For this to work end to end:
- Logs must carry `TraceId` and `SpanId` (automatic once OTel logging is wired, see `logs.md`).
- Profiles must carry the same `service_name` and (for span profiles) the span id (see `profiling.md`).
- Same resource identity on all signals.
